# CHB‑MIT Cohort Pipeline (Approach 4)

## Repository structure
```
README.md            <-- this file (you are reading it)
context.md           <-- architectural decisions
cohort_pipeline.py   <-- main preprocessing + CV + model training
approach4_pipeline.py <-- channel‑selection utilities
make_notebook.py     <-- script that builds the Jupyter notebook
test_cv_grouping.py  <-- unit‑test ensuring patient‑level LeaveOneGroupOut
processed_dataset/   <-- generated .npy/.csv files (X_cohort.npy, y_cohort.npy, patient_ids.npy, recording_ids.npy, metadata_cohort.csv, seizure_events_metadata.csv)
output/              <-- plots, metrics CSV, generated notebook
requirements.txt    <-- Python dependencies
```

### Files you need to push to GitHub
- All **source** files (`*.py`).
- `requirements.txt`.
- `README.md` and `context.md`.
- **Do NOT** push the large binary `.npy` files in `processed_dataset/`; they can be regenerated by running the pipeline. If you want to share a snapshot, add them to a separate data release.
- The `output/` directory is optional – it contains generated plots and the notebook after a run.

### How to run the pipeline
```powershell
# From the project root
python cohort_pipeline.py
```
The script will:
1. Load all EDF recordings (default: all patients).
2. Extract epochs, compute features, and save the arrays into `processed_dataset/`.
3. Perform patient‑level LeaveOneGroupOut CV, train a RandomForest, and write metrics to `output/cohort_model_evaluation_metrics.csv`.
4. Generate the notebook (`output/Approach4_CHB01_Preprocessing_EDA.ipynb`).

### FAQ
**Q: Can I run the pipeline on a selected list of patients?**
Yes. Edit the global variable `SELECTED_PATIENT_IDS` near the top of `cohort_pipeline.py` (or pass it as a command‑line argument). For example:
```python
SELECTED_PATIENT_IDS = ['chb01', 'chb03']  # only process these patients
```
The script will filter the dataset accordingly, so you do not need to modify any other code.

**Q: Can I run it on multiple targets at once?**
The pipeline already processes **all recordings** for the chosen patients in one run. If you want to run separate experiments (e.g., different feature sets), you can invoke `cohort_pipeline.py` multiple times with different configuration flags – each run will write its own output files, leaving previous results untouched.

**Q: Where are the hyper‑parameters?**
All configurable settings live at the top of `cohort_pipeline.py` (window size, step, feature list, random‑forest parameters, etc.). Adjust them as needed before re‑running.
